# 软著申请版本倒排计划（目标：2026-10-15）

> 项目：基于 CARLA 的自动驾驶极端场景生成与仿真测试系统 V1.0
> 计划用途：申请版本范围冻结、材料准备和提交前核对；不替代当期官方申请指南、申请表或主管部门审核。
> 编制日期：2026-09-23

## 一、目标与口径

目标是在 2026-10-15 前完成申请材料包并提交准备。这里的“完成”包括：申请主体信息已确认、申请版本已冻结、软件说明书和操作截图已从同一提交生成、源代码鉴别材料已整理、材料清单已逐项复核。受理、审查和登记结果取决于官方系统和主管部门，不把提交准备等同于登记成功。

申请版本名称暂定为：基于CARLA的自动驾驶极端场景生成与仿真测试系统 V1.0。最终名称、版本号、著作权人、开发完成日期和权利归属必须在提交前由项目负责人确认。

## 二、申请版本冻结范围

申请版本只写入当前已经实现并可复核的功能：

1. M01 场景生成：LHS、条件 GMM、条件表格 CVAE 和轻量条件 Diffusion 的参数级生成入口及统一 JSON/JSONL 输出。
2. M02 约束校验：Schema、语义约束、参数级物理约束和 CARLA 配置编译。
3. M03 场景库：117 个独立场景、351 条来源批次严格验收证据、结构化查询和只读 Web 展示。
4. M04 仿真采集：CARLA 0.9.16、RGB/Depth/SemSeg/Collision 证据配置、路线和服务健康验收；说明书按实际证据范围描述。
5. M05 风险评估：基于仿真遥测的 heuristic_v2 风险分解和结果展示；不写事故概率或真实道路安全结论。
6. M06 实验与任务编排：CPU 离线任务、任务状态、结果产物、工作流关联和证据哈希；CARLA 任务为显式外部执行登记。
7. M07 Web 管理：Dashboard、场景列表/详情、生成、校验、风险分析、任务详情和生成到校验连续流程。
8. M08 一键最小演示：离线静态校验、配置编译、场景库查询、OpenSCENARIO 最小适配、历史证据汇总和 demo_manifest.json。

## 三、明确不写入本版本的能力

以下内容不作为申请版本已实现功能或效果承诺：

- 候选场景工作区和正式场景库写入审批流；
- Web 自动启动 CARLA、服务器 Job 自动回链、多用户、权限和生产部署；
- CARLA 在线 RL 的总体风险提升、普遍泛化或策略效果保证；
- ScenarioRunner 跨地图、批量完整语义和 OpenSCENARIO 原生多传感器/风险语义；
- 真实 PyBullet/MJX 可微车辆物理训练闭环；
- 场景库真实性、行业覆盖率、实车成本、90% 成本降低、11 倍效率、90% 覆盖率等未经同口径实测的宣传指标；
- 10,000 场景扩库作为已完成规模。

## 五、倒排节点

### 2026-09-23 至 09-29：口径锁定

- 完成申请版本范围和不纳入项确认。
- 更新 PROJECT、材料台账、材料索引和用户操作说明。
- 检查软件名称、版本号、M01–M08 名称和 target_risk_level/observed_risk 术语。
- 不再新增高风险研究实验；只修复影响申请版本主流程的缺陷。

### 2026-09-30 至 10-06：材料初稿与证据重建

- 在候选冻结提交上运行全量测试、compileall、Web HTTP 回归和 M08 一键演示。
- 确认 Web 生成→校验→任务详情主流程可复现。
- 重新生成 demo_manifest.json、轻量报告和产物 SHA-256。
- 形成软件说明书初稿、模块说明、接口清单和截图采集清单。

### 2026-10-07 至 10-12：申请版本预冻结

- 停止申请版本功能开发，只处理 P0 阻塞和材料一致性问题。
- 从同一候选提交采集 Web 截图：Dashboard、场景库、详情、生成、校验通过、校验失败、风险、任务详情、M08 输出。
- 运行 tools/check_stage5_freeze.cmd，逐项关闭 FAIL；PENDING 项要么补证据，要么在申请包中明确标注不适用/后置。
- 复核源代码鉴别材料不包含密钥、服务器路径、个人隐私和大体积原始帧。

### 2026-10-13：冻结日

- 建立申请版本 Git tag/提交，记录提交哈希和运行环境。
- 冻结软件名称、版本号、功能范围、截图、说明书和源代码鉴别材料。
- 冻结后只允许修复会导致材料无法提交的阻塞问题；任何功能变更都必须重新评估是否回滚冻结。

### 2026-10-14 至 10-15：提交准备

- 按当期官方要求逐项核对材料格式、页数、文件大小、签章/主体信息和上传字段。
- 复核申请表、说明书、源代码鉴别材料、截图、版本号和提交哈希相互一致。
- 形成最终材料包校验记录；目标 10 月 15 日提交申请。

## 六、冻结质量门

申请版本进入提交准备前，必须满足：

- Web 主流程真实 HTTP 回归通过：生成、校验、任务详情和错误展示可复现。
- 全量自动化测试通过；可选依赖跳过项被单独记录，不冒充训练能力。
- compileall 和 git diff --check 通过。
- M08 demo_manifest.json 状态为通过，且 carla_connected=false、new_carla_risk_evaluation=false 口径正确。
- 场景库数量和证据口径保持 117/351，真实性仍标记 not_assessed。
- 所有截图、说明书、接口规格和代码均来自同一冻结提交。
- CARLA 相关文字区分静态适配、历史实机证据和未完成泛化能力。
- 申请包不含模型权重、原始传感器帧、密钥、服务器凭据和用户隐私。

## 七、提交后的继续迭代

软著提交后，继续产品化不受本申请版本限制。后续版本可单独推进候选场景工作区、服务器 Job 状态回链、多用户权限、跨地图 ScenarioRunner 和更严格的风险/真实性研究；这些改动不得回写成 2026-10-15 申请版本已经具备的功能或证据。
